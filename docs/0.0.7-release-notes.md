Seventh Apple Silicon alpha prerelease. tern takes on its design language: a new default theme
that follows macOS light and dark, redrawn status marks, and a rebuilt Settings window with search.
The app targets macOS 14 or later; testing on macOS 14 and on a separate Mac is still outstanding.

## Changes since 0.0.6

### The tern theme

- The new default theme, `tern`, follows macOS's light or dark appearance and switches with it,
  terminal included. The terminal sits on the darkest ground, and its 16 colours are a new palette
  that stays readable on both.
- Amber marks what needs you, and also tints switches, links, focus rings and progress. The
  selected row and primary buttons are filled cream in dark mode and navy in light mode. Working
  status is neutral grey.
- Graphite, Midnight, Ember, Paper and the Ghostty theme are still there and keep their colours.
  They pick up the new controls and status marks.
- If you never chose a theme, you get `tern`. A theme you chose is kept; pick `tern` in Settings →
  Appearance, or set `theme = tern` in the config file, to switch.

### Status marks

- Each kind of session has its own mark: an agent's logo on a small tile, a pill for a shell, and
  a square for a program that reports its status with OSC 7501. A hollow mark means working. The
  sidebar, collapsed folders and the content header use the same marks.

### Settings

- Settings is rebuilt as a sidebar of panes with a search field that finds any setting by name,
  description or config key. Choosing a result opens its pane and highlights the row. ⌘F focuses
  the search field.
- Each row shows the config file key it writes.
- Settings → Agents adds the ntfy URL for phone pushes (`notify-ntfy`) and how long until you
  count as away (`away-after`).
- Problems in the config file, and where it's saved, show at the foot of the window.

## Install

Download `Tern-0.0.7-macos-arm64.zip` and its `.sha256` file, then verify them:

```sh
shasum -a 256 -c Tern-0.0.7-macos-arm64.zip.sha256
```

Unzip it and move `Tern.app` to Applications. The app is signed with Developer ID, notarized and
carries a stapled ticket. Intel Macs need a separate build.

Upgrading from 0.0.6: tern → Check for Tern Updates… finds this release. The daemon protocol is
unchanged, so the running ternd keeps working and your tabs carry on; restart it when it suits
you.

The source bundle includes tern, the pinned Ghostty checkout, fetched native dependency sources
and vendored Rust crates. `SOURCE_BUILD.md` in that archive records the exact commits and rebuild
instructions. The source bundle has its own SHA-256 checksum.

## Known limitations

- Only the `tern` theme follows macOS's appearance; the others look the same in light and dark.
- The command palette and the folder picker still mark the selected row in grey.
- On a device, Show in Finder and worktrees don't work yet, and dropping a file or pasting an
  image types this Mac's path. ⌘-click there needs VS Code, Cursor or Zed as the editor, and Zed
  opens the file without going to its line.
- `tern split`, `tern tab` and the other pane commands, run inside a device's pane, don't reach
  the app.
- A device's ternd reads its own `~/.config/tern/config` for `on-<event>` commands and
  `notify-ntfy`, and can't tell whether you're at the Mac, so it counts you as always away.
- After updating tern, a device keeps its older ternd until you restart it from Settings →
  Devices.
- Device support has been tried against x86_64 Linux. ARM Linux and a second Mac as a device are
  untested.
- When the CLI changes a window's layout at the same moment as you do, the CLI's change wins.
- Copy/paste inside Codex is an open issue.
- A reboot or daemon restart ends running processes; saved screens return and supported agent
  conversations can resume.
- Agent updates and shell integration have been tried with zsh only.
