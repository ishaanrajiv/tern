Sixth Apple Silicon alpha prerelease. Folders on other machines now sit in the sidebar beside
this Mac's, with their sessions running on that machine: a Linux box or another Mac you reach over
SSH. ternd and the tern CLI run on Linux for this. The app targets macOS 14 or later; testing on
macOS 14 and on a separate Mac is still outstanding.

## Changes since 0.0.5

### Devices

- Add a machine in Settings → Devices, by an SSH alias from `~/.ssh/config` or `user@host`, or
  with a `device = <host>` line in the config file. Ports, keys and jump hosts come from your SSH
  config; tern uses your keys and agent and never stores a password.
- In ⌘N, type a device's name and a colon (`devbox:`) for its recent folders and repositories, or
  a path (`devbox:~/dev/`) to browse its folders as you type.
- A device's folders and tabs work like local ones: splits, the branch, agent status, the Dock
  badge, ⌘J and notifications. Their sessions run on the device, so they keep running while this
  Mac sleeps, quits tern or loses the network, and come back when it reconnects. The folder
  header's chip names the device and shows a dot while it isn't connected.
- The first time, tern copies its own `tern` and `ternd` to `~/.local/share/tern` on the device:
  static builds for x86_64 and ARM Linux that run on any distribution, or this app's own for an
  Apple Silicon Mac. It updates them when the app changes and keeps the three newest builds.
- A device that wants a password or a host key confirmed asks once, in a pane, through your own
  `ssh`. tern never accepts a host key for you.
- Settings → Devices shows each connection and why one failed, sets up Claude Code and Codex hooks
  on the device, and restarts its ternd after an update, which ends the programs running there.
- ⌘-click and Open Selected File in a device's pane open the file on the device: VS Code and
  Cursor through Remote - SSH, Zed through its SSH remoting.
- Each Mac's sessions on a device become tabs only on that Mac. Detached Sessions shows where each
  session runs and marks the ones another Mac started.

### How it works

One SSH connection per device carries every pane, through `tern link` on this Mac and `tern proxy`
on the device. It offers the device's ternd as a local socket, so `tern attach --host`, `tern ls
--host` and `tern kill --host` reach it like the local one. Nothing listens on a network port on
either machine. `tern link <device> --status` prints a link's state.

### Linux

- ternd and the tern CLI build and run on Linux, as static musl binaries for x86_64 and aarch64
  (`scripts/build-remote.sh`). The app bundles both. On Linux ternd starts on demand rather than
  through launchd, and stays running after the SSH session that started it ends.

## Install

Download `Tern-0.0.6-macos-arm64.zip` and its `.sha256` file, then verify them:

```sh
shasum -a 256 -c Tern-0.0.6-macos-arm64.zip.sha256
```

Unzip it and move `Tern.app` to Applications. The app is signed with Developer ID, notarized and
carries a stapled ticket. Intel Macs need a separate build.

Upgrading from 0.0.5: tern → Check for Tern Updates… finds this release. The daemon protocol is
unchanged, so the running ternd keeps working and your tabs carry on; restart it when it suits
you. A device needs nothing installed beforehand beyond an SSH server and a POSIX shell.

The source bundle includes tern, the pinned Ghostty checkout, fetched native dependency sources
and vendored Rust crates. `SOURCE_BUILD.md` in that archive records the exact commits and rebuild
instructions. The source bundle has its own SHA-256 checksum.

## Known limitations

- On a device, Show in Finder and worktrees don't work yet, and dropping a file or pasting an
  image types this Mac's path. ⌘-click there needs VS Code, Cursor or Zed as the editor, and Zed
  opens the file without going to its line.
- `tern split`, `tern tab` and the other pane commands, run inside a device's pane, don't reach
  the app.
- A device's ternd reads its own `~/.config/tern/config` for `on-<event>` commands and
  `notify-ntfy`, and can't tell whether you're at the Mac, so it counts you as always away.
- After updating tern, a device keeps its older ternd until you restart it from Settings →
  Devices.
- Device support has been tried against x86_64 Linux. ARM Linux and a second Mac as a device are
  untested.
- When the CLI changes a window's layout at the same moment as you do, the CLI's change wins.
- Copy/paste inside Codex is an open issue.
- A reboot or daemon restart ends running processes; saved screens return and supported agent
  conversations can resume.
- Agent updates and shell integration have been tried with zsh only.
