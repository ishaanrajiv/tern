Fifth Apple Silicon alpha prerelease. Programs can report their own status, and agents and scripts
can open and drive panes from the command line. ternd runs commands when something happens in your
panes and can push to your phone while you're away. Every setting now lives in a plain config file.
The app targets macOS 14 or later; testing on macOS 14 and on a separate Mac is still outstanding.

## Changes since 0.0.4

### Program status

- Any program can say it is idle, working, blocked, done or failed with the OSC 7501 program
  status protocol: a build, a deploy script, or an agent without hooks. ternd answers the
  protocol's support query and keeps one record per task.
- Programs that aren't agents get a rounded-square glyph and a progress ring. The header shows
  their message, why they're blocked ("Permission: …") and how many tasks they're running. They
  count for ⌘J and the Dock badge like agents do.
- A new red **Failed** state shows in rows, collapsed folders and the header.
- Work in progress clears at the next prompt, and a result clears once you press a key in that
  pane. A result you haven't seen survives a ternd restart with the screen. When an agent's hooks
  and its own report disagree, the newer one wins.

### Driving panes from agents and scripts

- New commands: `tern split`, `tab`, `send`, `capture`, `wait`, `close`, `run`, and `ls --json`
  with every window's folders, tabs and splits. ternd keeps the layouts now, so they work with
  the app quit and answer with the id of the pane they made.
- Commands act on the pane they run in by default. `--pane` takes an id, a name or `@focused`,
  and `--tab` an id or a name. A target that matches nothing, or several panes, gets its own exit
  code.
- `tern wait` waits for the shell's prompt, a command's exit, a line of text (a regular
  expression) or an agent's state, with a timeout. `tern run` runs a command in a pane beside
  you and returns its output and exit code.
- Panes an agent opens stay in the background unless it passes `--focus`. Their header says
  which agent opened them.
- Settings → Agents → Set Up also installs a `tern` skill for Claude Code and Codex, which
  teaches them these commands. If hooks are already set up, tern adds the skill at launch. A
  skill of your own called `tern` is left alone.

### Events and notifications

- `tern watch` prints events as they happen; `--json` gives one object a line. The events are
  `needs-you`, `working`, `done`, `failed`, `command-done`, `command-failed`, `bell`, `start` and
  `exit`.
- `on-<event>` lines in the config file run a command when an event happens, with its details in
  `TERN_*` variables. ternd runs them, so they work with the app quit.
- ternd can push to your phone through ntfy while you're away from the Mac: tern isn't in front,
  and the screen is locked or there has been no input for two minutes. Only a title is sent, like
  "Claude Code needs you · api", never what the agent asked or a command line.
- Notification banners failed because macOS had them recorded as denied: a permission request
  that goes unanswered counts as a no, and macOS never asks again. It wasn't a signing problem.
  Settings → Agents now says when they're off and opens System Settings → Notifications at tern's
  entry.

### Config file

- Every setting lives in `~/.config/tern/config` (or `$XDG_CONFIG_HOME/tern/config`), one
  `key = value` a line in Ghostty's style. Settings writes to it, changing only the lines it needs
  to, and your own edits apply as soon as you save. The README lists every key.
- A line tern can't use keeps the last good value and is listed in Settings → General, which also
  opens the file. Reload Configuration rereads it.
- Terminal settings use Ghostty's own key names, and only the keys the file gives override your
  Ghostty config.
- Launch presets are JSON files in `~/.config/tern/presets/`, one per preset.
- The config and presets are readable only by you, and a config kept in a dotfiles repository
  stays a symlink.
- A private instance (`TERN_RUNTIME_DIR`) reads its own config and keeps its settings apart from
  the installed app's.

## Install

Download `Tern-0.0.5-macos-arm64.zip` and its `.sha256` file, then verify them:

```sh
shasum -a 256 -c Tern-0.0.5-macos-arm64.zip.sha256
```

Unzip it and move `Tern.app` to Applications. The app is signed with Developer ID, notarized and
carries a stapled ticket. Intel Macs need a separate build.

Upgrading from 0.0.4: tern → Check for Tern Updates… finds this release. **The daemon protocol
moves from 2 to 3**, so the new app needs the new ternd. Until ternd restarts, a sheet and the
update card ask you to restart it, and the new commands and events aren't available. A restart
ends the programs running in your tabs; their screens come back and agent conversations resume.

On first launch, the settings you changed, your terminal settings and your launch presets move
into `~/.config/tern`. The old files in `~/Library/Application Support/tern` stay, for going back
to 0.0.4.

The source bundle includes tern, the pinned Ghostty checkout, fetched native dependency sources
and vendored Rust crates. `SOURCE_BUILD.md` in that archive records the exact commits and rebuild
instructions. The source bundle has its own SHA-256 checksum.

## Known limitations

- Notifications stay off if macOS's first request went unanswered; turn them on from Settings →
  Agents. Dock badges and ⌘J don't depend on them.
- When the CLI changes a window's layout at the same moment as you do, the CLI's change wins.
- Copy/paste inside Codex is an open issue.
- A reboot or daemon restart ends running processes; saved screens return and supported agent
  conversations can resume.
- Saved screens don't capture a full-screen program's screen or image pixels, and agent
  completion is inferred without hooks.
- Launch-preset environment values and saved terminal output are local plaintext files,
  readable only by you.
- Agent updates and shell integration have been tried with zsh only.
