## First release scope

- App version and Rust package version `0.0.1`, with tag `v0.0.1`.
- Native `arm64` build. Intel and universal binaries are outside this release.
- Developer ID signing, hardened runtime, secure timestamps, notarization and a stapled ticket.
- A versioned ZIP, SHA-256 checksum, release notes and the sources/rebuild materials needed
  for the bundled dependencies.
- A GitHub prerelease in the existing private repository, initially prepared as a draft.
  Its downloads will require repository access. Making the source public is a separate decision.
- No new terminal features, updater, or seamless daemon upgrades in this release.

The deployment target is macOS 14. A successful build on a newer Mac does not verify
that minimum. Test the downloadable artifact on the oldest claimed supported version
before describing it as tested there.

## Release preparation

The release branch, `0.0.1` version and packaging scripts were merged. Signing setup is
verified. Build results and uploaded assets are recorded in the published GitHub prerelease.
The sequence below records the preparation workflow, including its initial draft stage.

1. Create a fresh `codex/release-0.0.1` branch from current main. Update
   `app/Info.plist`, `crates/tern/Cargo.toml` and `Cargo.lock` from `0.1.0` to `0.0.1`.
   Keep `CFBundleVersion` increasing for subsequent distributed builds.
2. Adapt the small release packaging changes from the old PRs: locked Cargo builds,
   `Tern-0.0.1-macos-arm64.zip` and its `.sha256` file. Keep the current build's
   libghostty-vt integration and `Contents/Helpers` placement.
3. Record the exact tern and Ghostty commits. Review bundled notices and prepare the
   dependency sources and rebuild instructions. GitHub's automatic source archive is
   insufficient because it omits the Ghostty submodule and fetched dependencies.
   `python3 scripts/package-source.py` packages a clean committed checkout, includes
   vendored Rust crates and native sources, and writes rebuild instructions and a checksum.
4. Run the repository checks and build a distribution candidate:

   ```sh
   ./scripts/check.sh
   ./scripts/build-app.sh --dist
   ```

5. Verify all executables are arm64, the bundle version is correct, signatures and
   notarization pass, and the checksum matches the final stapled ZIP.
6. Smoke-test the actual download on a separate Mac with normal download quarantine.
   Check input, text copy/paste in shell and Codex, splits, find, quit/relaunch reattachment,
   layout recovery, agent status, hook setup/removal, presets and SSH.
   Use a short private `TERN_RUNTIME_DIR` for local experiments. Do not restart the
   maintainer's normal daemon or rewrite their real agent configuration during tests.
7. Prepare release notes that describe the tested support range and known limitations.
   Investigate the documented Codex copy/paste issue before expanding distribution.
   Notification banners may remain a disclosed alpha limitation; verify Dock badge and
   next-agent navigation independently.
8. Tag the exact tested commit and attach the verified ZIP, checksum and source/rebuild
   materials to a draft GitHub prerelease. Publish the prerelease after checking the
   uploaded artifacts. Keep repository visibility private until the public review is resolved.

Reference: [GitHub release access and tags](https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases).

## Fixes retained for follow-up

These issues remain in main. Closing the old PRs does not resolve them.

| Follow-up | Useful source | Adaptation needed |
|---|---|---|
| Validate session IDs before every operation that reaches filesystem paths | Both PRs | Cover attach, kill, report, saved files, command files and `.done` files. Bound the ID including filename suffixes. PR #2's 255-byte ID limit leaves no room for `.screen.tmp`. |
| Make runtime storage private and verify socket peer UID | Both PRs; peer check in #2 | Secure the runtime directory, subdirectories, socket and files. Reject a symlinked root before chmod. Preserve the intentional CLI symlink and never chmod its target. Review existing storage recovery behavior. |
| Bound request lines, frames and output queues | Both PRs | Account for the client's environment in the attach request. Preserve final output and exit ordering, wake blocked writers on disconnect, and test a stalled client. |
| Bound replay snapshots | #2 | Use libghostty-vt, preserving replay modes and valid escape sequences. The old vt100 history formatter cannot be carried over. Align producer and consumer limits and avoid reconnect loops. |
| Quote agent resume IDs and installed hook paths | #2 | Reuse current Swift `quoteShell` where appropriate. Recognize old hook quoting so upgrades remove only tern's entries. Preserve unrelated hooks and status lines. |
| Preserve agent configuration symlinks and modes | #2 | Test absolute and relative links, install twice, upgrade and uninstall. Audit backup paths at the resolved target. Do not infer file ownership from the presence of a backup. |
| Use the client's chosen shell and write the launchd plist safely | #2 | Keep current handshake, build ID and daemon mismatch handling. Test launchd-domain behavior separately before adding fallback behavior. |
| Exclude the event-driving debug harness from distributed builds | #2 | Keep debug validation available while ensuring a release build cannot enable it through `TERN_DEBUG`. Preserve Swift 6 main-actor settings. |
| Make Claude account polling opt-in with clear disclosure | #2 | Check both preference defaults and Settings, preserve explicit user choices, keep local statusline usage working, and never refresh Claude's token. |
| Verify fetched Zig dependencies | Both PRs | Combine #1's extracted-layout mismatch regression test with #2's `.tgz` support. Verify against the actual pinned Zig and dependencies, not only mocked tests. |
| Add required CI and public project documentation | #2 | Build libghostty-vt before Rust checks. Require Swift builds/tests rather than allowing the App job to fail. Update privacy documentation for current SSH and launch-preset behavior. |

Do not copy PR #2's queue unchanged. `push_exit` clears pending output, so the last
command's output can be lost. Removing a client also does not close or notify its
condition-variable queue, so an idle writer can stay blocked while attach joins it.
The runtime preparation also chmods the root before its later symlink check.
